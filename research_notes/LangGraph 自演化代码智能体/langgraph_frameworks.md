Method note. Star counts, creation and last-push dates, and licenses come from the GitHub search API (`gh api search/repositories`), queried 2026-11-07. ## Which LangGraph-based self-evolving code agents exist and how mature/active are they?

### Takeaway
LangChain's official material (tutorials, Deep Agents, open-swe/"Robin", LangMem) has mature, very active *within-task* self-correction loops. It also has *cross-session* learning through memory, skills and prompt optimization. It ships no official evolutionary or self-rewriting code agent. The true "self-evolving" LangGraph projects (population/archive, self-editing code or graph) are all small community prototypes, each under about 110 stars and mostly labelled alpha or experimental. No arXiv paper was found and confirmed to implement a self-evolving code agent in LangGraph. One LangGraph bug-fixing paper exists (iterative refinement, not evolution).

- **"Code generation with RAG and self-correction" tutorial** (LangGraph code assistant), inspired by AlphaCodium. Graph: `generate` → `check_code` → conditional `decide_to_finish` → {`end`, `reflect`, `generate`}, with a `reflect` node and `max_iterations = 3`. State holds `error`, `messages`, `generation`, `iterations`. `check_code` runs the import check and then exec of the code. Self-evolution here means only within-task repair from execution errors. Nothing persists across tasks. The notebook's own eval found that "adding re-try loop improve performance" but "Reflection did not help: reflection prior to re-try regression vs just passing errors directly back to the LLM". — [notebook @23961cf](https://github.com/langchain-ai/langgraph/blob/23961cff61a42b52525f3b20b4094d8d2fba1744/docs/docs/tutorials/code_assistant/langgraph_code_assistant.ipynb)
- **Reflexion tutorial** (after Shinn et al.). Nodes `draft` (first responder with self-critique) → `execute_tools` → `revise`, with conditional `event_loop` back to `execute_tools` or END. Domain is search Q&A, not code. The notebook concludes that it "trades off execution time for quality". — [notebook @23961cf](https://github.com/langchain-ai/langgraph/blob/23961cff61a42b52525f3b20b4094d8d2fba1744/docs/docs/tutorials/reflexion/reflexion.ipynb)
- **LATS tutorial** (Language Agent Tree Search, Zhou et al.). Nodes `start` (initial response + reflection score) and `expand` (generate N=5 candidates from the max-UCB node, reflect and score, backpropagate), with conditional `should_loop` to `expand` or END. The tree lives in graph state. The notebook says that for grounded tools such as code synthesis, execution results can serve as the reward. It notes that "the tree rollout can take additional compute time". — [notebook @23961cf](https://github.com/langchain-ai/langgraph/blob/23961cff61a42b52525f3b20b4094d8d2fba1744/docs/docs/tutorials/lats/lats.ipynb)

### Inferences
- Maturity is strongly bimodal. Official LangChain projects (deepagents 31k★, open-swe/Robin 11k★, LangMem 1.7k★) are active but mostly do *bounded* self-improvement: memory, skills, prompt edits and learned review preferences. ## What graph patterns recur for self-evolution, and what are their trade-offs?

### Takeaway
There are six recurring patterns, ordered from cheapest/bounded to most open-ended:
1. Generate → execute/test → (reflect) → regenerate cycle with a max-iteration cap.
2. Main-agent ↔ critic subgraph.
3. Tree search over candidates (LATS: expand + reflect-score + UCB backprop).
4. Post-run reflector → curator → persistent memory/playbook/skill store (Voyager/ACE/LangMem).
5. Prompt-optimizer node over traces (LangMem gradient/metaprompt).
6. Outer evolutionary loop (archive → select parent → meta-agent mutates code/prompt/topology → sandboxed eval → archive).

Trade-offs run from cost/latency and evaluator quality to safety/regression risk.

### Cited Findings
- **Pattern 1, execution-feedback repair loop** (`generate`/`check_code`/`reflect`, `max_iterations=3`). The official eval found that the retry loop helps, but a separate reflection step *hurt*: passing errors straight back worked better. — [LangGraph code assistant notebook](https://github.com/langchain-ai/langgraph/blob/23961cff61a42b52525f3b20b4094d8d2fba1744/docs/docs/tutorials/code_assistant/langgraph_code_assistant.ipynb)
- **Pattern 2, critic subgraph** (langgraph-reflection): terminates when the critic returns no message. This is simple, but quality depends on the critic, and it can loop. — [langgraph-reflection README](https://github.com/langchain-ai/langgraph-reflection)
- **Pattern 3, tree search** (LATS): N=5 candidates per expansion, UCB selection, reflection-as-reward. Better on hard reasoning, but "the tree rollout can take additional compute time". — [LATS notebook](https://github.com/langchain-ai/langgraph/blob/23961cff61a42b52525f3b20b4094d8d2fba1744/docs/docs/tutorials/lats/lats.ipynb)
- **Pattern 3b, early-exit judge**: a cheap LLM judge decides when more attempts stop paying off, to cut tokens (hypothesis; no results published yet). — [token-efficient-self-improving-agent](https://github.com/absyed-lab/token-efficient-self-improving-agent)
- **Pattern 4, experience memory/playbook/skills**:
  - ACE's Generator → Evaluator → Reflector → Curator → Playbook. — [ace-langgraph](https://github.com/pingcy/ace-langgraph)
  - Reflexion with episodic lessons across attempts. — [langgraph-reflection-agent](https://github.com/MartinCastroAlvarez/langgraph-reflection-agent)
  - Voyager reusable Python skills. — [all-agentic-architectures](https://github.com/FareedKhan-dev/all-agentic-architectures)
  - Runtime-written, hot-installed skills. — [FrontDesk AI](https://github.com/brainupgrade-in/aiagentic-comp-frontdeskai)
  - Deep Agents skills + persistent memory store backends. — [deepagents](https://github.com/langchain-ai/deepagents)
- **Pattern 5, prompt self-optimization**: LangMem `gradient` (2 or more LLM calls: critique, then apply), `metaprompt`, and `prompt_memory` (1 call). Gradient is the costliest. — [LangMem reference](https://langchain-ai.github.io/langmem/reference/prompt_optimization) [snippet]; [classmethod tutorial](https://dev.classmethod.jp/articles/python-litellm-online-learning/) [snippet]
- **Pattern 6, outer evolutionary loop**: HyperFlow's archive + parent selection + MetaAgent code edits + Docker eval. — [HyperFlow](https://github.com/lablnet/HyperFlow). Graph-topology evolution with a deterministic evaluator and elitist champion. — [self-evolving-langgraph](https://github.com/kooroshIM99/self-evolving-langgraph). Islands + crossover + migration. — [Mind-Evolution-PoC](https://github.com/AlanoHater/Mind-Evolution-PoC). MAP-Elites over agent genotypes. — [qd-langchain-agents](https://github.com/FareedKhan-dev/qd-langchain-agents)
- Practitioner guidance: restrict self-evolution to well-bounded capability improvements. — [DEV Community](https://dev.to/richard_dillon_b9c238186e/ai-agent-skills-the-emerging-architecture-for-composable-evolvable-agent-capabilities-23ao) [snippet]. SenseLab/AMFS explicitly gates corrections on outcomes and keeps them reversible and logged. — [amfs README](https://github.com/raia-live/amfs)
- [snippet] Deep Agents' cross-deployment memory is reportedly not solved by the framework itself. — [memU blog](https://memu.pro/blog/langchain-deep-agents-long-horizon-memory)

### Inferences
- LangGraph's primitives map naturally onto patterns 1–5:
  - conditional edges suit retry and critic loops;
  - state/reducers hold trees and populations;
  - the checkpointer/Store holds memory and skills;
  - `Send` fan-out suits parallel candidates.
- Pattern 6 is usually implemented as a plain Python outer loop around LangGraph inner agents (HyperFlow's `generate_loop.py`, self-evolving-langgraph's `graph_runtime.py`), not as a single graph. LangGraph is the inner-agent runtime rather than the evolutionary engine.
- Key trade-off axes:
  1. Evaluator fidelity: deterministic tests or exit codes beat LLM judges (the official notebook's reflection result, and self-evolving-langgraph's deterministic scoring).
  2. Cost: tree search and populations multiply LLM calls.
  3. Persistence risk: memory, skill and prompt updates can drift or regress, so gated promotion, versioning and rollback matter (AMFS; skillforge "防退化版本晋升", i.e. anti-regression version promotion).
  4. Safety: self-edited code needs sandboxes (Docker in HyperFlow, I.S.A.A.C, autodev).

### Gaps
- No controlled comparison of these patterns in LangGraph on a common code benchmark was found. The only quantitative statements are the code-assistant notebook's qualitative eval and the secondary report of the Terminal Bench harness result.

## Are there LangGraph implementations of AlphaEvolve/OpenEvolve-style evolutionary search?

### Takeaway
No official one, and no well-known community one. GitHub repo searches for "langgraph alphaevolve" and "langgraph openevolve" returned zero results (2026-11-07). Web search also found no LangGraph AlphaEvolve implementation. The closest LangGraph-based evolutionary loops are HyperFlow (archive-based DGM/HyperAgents-style self-modification), self-evolving-langgraph (topology/prompt evolution), Mind-Evolution-PoC (island GA over solutions), and qd-langchain-agents (MAP-Elites over agent configs). All are tiny and experimental, and none evolves arbitrary programs against a numeric evaluator the way OpenEvolve does.

### Cited Findings

### Inferences
- Anyone wanting AlphaEvolve-in-LangGraph today would build it themselves. A plausible mapping, based on the patterns above:
  - **nodes**: `sample_parents` (from a MAP-Elites/island DB held in the LangGraph Store), `build_prompt`, `mutate` (LLM diff generation, fanned out via `Send`), `evaluate` (sandboxed evaluator cascade), `update_db`;
  - **conditional edge**: generation/budget check.
- Alternatively, wrap OpenEvolve as a tool or subgraph inside a Deep Agent. The fact that every mature evolutionary-code system uses a custom asyncio loop suggests LangGraph's per-step checkpointing overhead offers little benefit at thousands of evaluations. This is an inference, not measured.
